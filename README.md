# 网络连接查看与切换工具

一个 Windows 桌面小工具（PowerShell + WinForms，无需安装任何运行库）：
界面实时显示当前网络连接信息，并提供两个按钮 —— **本地网络切换** 和 **切换到 WiFi**。

> **切换原理：调整「接口跃点数（Interface Metric）」，只改变实际流量出口，**
> **两块网卡始终保持启用，不断开任何网卡，因此可以随时来回切换、不会把自己切断线。**

## 文件说明

| 文件 | 说明 |
| --- | --- |
| `启动网络切换工具.bat` | 双击这个启动（推荐）。不弹控制台黑框，需要时会弹 UAC 提权。 |
| `NetworkSwitchTool.ps1` | 主程序（全部逻辑都在这里，可直接编辑）。 |
| `config.json` | 保存你选择的网卡、WiFi、跃点数值。 |
| `switch-log.txt` | 运行日志，记录每次切换动作和结果。 |

## 使用方法

1. 双击 `启动网络切换工具.bat`。
2. 弹出 UAC 时选「是」（调整跃点数、读取无线信息都需要管理员权限）。
   - 选「否」也能打开界面查看连接信息，只是不能执行切换。
3. 点「设置…」选择：
   - **本地网络 A / 本地网络 B**：两块有线网卡之间切换用（只走有线的场景）。
   - **无线网卡**：一般是 `WLAN`。
   - **WiFi 名称**：下拉列出**当前可见的无线网络**（标注信号强度、是否已保存配置）以及已保存但当前不可见的网络；也可以直接手打 SSID。
     > 读不到可见列表时，需在「设置 → 隐私和安全性 → 位置」打开**位置服务**（Win11 限制，`netsh` 才允许列出无线网络）。留空则每次自动挑选"可见且已保存"里信号最强的那个。
   - **跃点数(首选/其它)**：默认 `10 / 1000`，首选网卡用左值、其它网卡用右值；数值越小越优先，左值必须小于右值。
   - **切换到 WiFi 时改为「禁用」本地有线网卡**：默认**不勾选**（只切流量，不断网）。
   - **网卡断开后自动把流量切到另一块可用网卡（WiFi↔有线、有线↔有线）**：默认**勾选**（见下面"自动切换"一节）。
   - **指定的 WiFi 连不上时，自动尝试其它可见且已保存的网络**：默认**勾选**（按信号强弱依次尝试）。
   - **WiFi 等待(秒)**：连接**单个**无线网络的最长等待，默认 `15`（可填 8～120）。想更快失败就调小，例如 `8`。
   - **自动刷新(秒)**：界面刷新间隔，默认 `3`（0 = 只手动刷新）。
4. 之后直接点主界面上的两个按钮即可。

## 两个按钮的行为

> **无弹窗、秒切**：两个按钮都**不再弹确认框**，成功后也**不弹提示框** —— 结果直接显示在
> 底部状态栏 + `switch-log.txt`（例如：`已切到 WiFi [Hi~] 信号 88%  (2.4s)  跃点 WLAN=20←出口，以太网=2000`）。
> 只有在"做不了 / 失败"时才弹窗：网卡不存在、目标网络没有默认网关、WiFi 连不上、校验未通过、需要管理员权限。
> 典型切换耗时约 **1～2 秒**（切到 WiFi 要等无线连接和拿地址，通常 3～10 秒）。

**本地网络切换（本地网络 A ↔ 本地网络 B）**

1. 先判定当前默认路由实际走的是哪块网卡，然后把流量出口切到**另一块**（用 `lastTarget` 记忆保证严格 A↔B 交替）。
2. **改接口跃点**：目标网卡 = 10，其它网卡 = 1000，并**关闭"自动度量"**（不关的话 Windows 会把手动值覆盖回自动值）。
3. **改默认路由自身的跃点**（`route change`）—— **这一步才是决定性的**，详见下面的"为什么只改接口跃点不够"。
4. **按路由表校验**：只有"目标网卡的默认路由生效跃点最小"才算成功；若仍打平或不是最小，就**删掉其它默认路由**，只留目标那条（绝对确定）。
5. 全程**不启用、不禁用任何网卡**，随时可以再点一次切回来。

> **已建立的连接不会迁移**：已经打开的网页、正在进行的下载/直播会继续走原来的出口（socket 已绑定源地址）。
> 验证切换请**新开一个页面**或用新的下载任务。

- 如果目标网卡当前是**禁用**状态，会先自动启用它，等它拿到默认网关后再切（这是"启用目标"，不是"禁用来源"）。
- 如果目标网卡启用了但拿不到默认网关（网线没插 / 该网络未联网），会提示并**保持原样**，不做任何修改。

**有线 ⇄ WiFi（双向切换，原来只能单向切到 WiFi）**

按钮会**自动判断方向**，点一下即可来回切：

| 当前出口 | 点一下之后 |
| --- | --- |
| 有线（以太网…） | **切到 WiFi**：启动无线服务 →（必要时）启用无线网卡 → 连接 WiFi（配置的 SSID，或自动挑"可见且已保存"里信号最强的）→ 等拿到 IP → 把流量出口切到 WLAN |
| WiFi（WLAN） | **切回有线**：优先切回上次那块有线网卡（`lastWired` 记忆；如果它之前被禁用过会自动启用），把流量出口切回有线 |

- 连接无线用 `netsh wlan connect name=<SSID> ssid=<SSID> interface=<网卡>`；每 5 秒重发一次连接请求（不主动断开，避免打断正在进行的关联）。
  **单个网络默认最多等 15 秒**（设置里可改 8～120 秒）；如果该网络**当前不在可见列表里，只快速试 6 秒就放弃**（快速失败，不再干等）；所有尝试加起来有总上限（默认 45 秒）。典型的成功连接 2～5 秒完成。
- **连接前先触发一次扫描**，并检查目标网络是否真的可见；扫不到就先记一笔（`[WiFi] 当前扫描不到「Hi~」；可见且已保存的网络：…`），仍然会尝试一次（可能刚好在扫描后出现）。
- **失败后会自动重置无线网卡**（禁用再启用）再重试一遍 —— 无线网卡经常卡在"正在连接 / 正在断开连接"状态，重置是唯一有效的恢复手段。
- **首选网络连不上时会自动尝试其它"可见且已保存"的网络**（按信号强弱排序，可在设置里关闭），连上后会明确告诉你连到了哪个 SSID。
- 失败弹窗和日志里会**列出当前可见网络（含信号、是否已保存）**，直接照着改选即可；读不到列表时会提示去打开位置服务。
- 会先检查无线服务 `WlanSvc`（没运行就启动）和**无线电开关**（飞行模式/硬件开关关闭时直接给出明确提示，不再傻等）。
- 检查到**已经连着 WiFi** 时不会重复连接，直接切流量出口。
- 全程**不禁用任何网卡**（除非你在设置里勾了"改为禁用本地有线网卡"），所以随时能再点一次切回去。
- 失败时**不做任何修改**：本地网络保持原样，不会因为切 WiFi 失败而断网。

## 自动切换：某块网卡断开后自动切到另一块

后台看门狗每轮刷新（默认 3 秒）检查一次，**分两路**，都受设置里「网卡断开后自动把流量切到另一块可用网卡」控制（默认开）：

**第一路 · WiFi 断开 → 切回有线**

1. 无线当前不可用（网卡不在线 / 没有默认网关 / `netsh wlan show interfaces` 显示未连接）；
2. 存在可用的有线网卡（在线 + 有默认网关）；
3. 此刻无线仍然比有线优先（出口是无线 / 完全没有出口 / 无线跃点更小）。

**第二路 · 有线 ↔ 有线（两块以太网互为备份）**

判定依据是**"跃点谁更优先"，与当前出口是谁无关** —— 这点很关键：网卡一断开，它的默认路由就消失，出口会自动漂到另一块，
若拿"出口是否可用"当判据就会误判成"无需处理"，于是**跃点一直不变、断开那块恢复后又把流量抢回去**。

规则：
- 目标 = 当前出口（可用时保持不动）→ 否则配置的「本地网络 A/B」→ 再否则任意可用本地网卡；
- 只要还有**另一块本地网卡的跃点不比目标差**（包括"已断开但跃点仍然更低"、以及**两块跃点打平**），就动手：
  目标 → `preferMetric`(10)，其它本地网卡（**含断开那块**）→ `deprioritizeMetric`(1000)。

这样三种情况都会被自动修正：断开那块恢复后抢流量、跃点打平导致出口随机、断开那块仍占着优先位。

> 尊重用户选择：如果本地网卡**全都是"自动度量"**（例如你刚点过「恢复自动跃点」），看门狗不会去打破这个平局。

两路共用一个 20 秒冷却，避免抖动。触发后写状态栏 + 日志：

```
[自动切换] 本地网卡之间竞争（目标=[以太网] 跃点=10），自动把优先出口固定到 [以太网]
  接口跃点 [以太网 3] = 1000
已把本地出口固定到 [以太网]  跃点 以太网=20←出口，以太网 3=2000
```

- **断开的网卡跃点也会被一起压到 1000** —— 否则它保留着低跃点，一恢复就会把流量抢回去。
- 自动切换**不弹窗**，只在状态栏/日志提示；失败也只在日志里写原因。
- 已知边界：如果 WiFi **显示为已连接但实际没有互联网**（例如路由器断了上行），操作系统无法察觉，本工具同样无法自动判断——这种情况需要手动点一下按钮。

## 已知限制与取舍

做完一轮独立代码审查后，以下是**已知**但有意保留或暂未处理的行为，用之前先知道：

1. **切到 WiFi 时，极端情况下会删掉其它默认路由。** 正常情况下切换只改跃点数（`route change`，不动路由表）。只有当"改完跃点、路由表却仍不认目标"时，才会退而删掉其它默认路由来强制切换 —— 现在这个兜底做了三层保护：删除命令带接口索引、用新鲜快照反查网卡（避免 DHCP 换址后认错）、删完会检查并**保证至少留一条默认路由**（被删空就立刻补回目标那条）。日志里会出现 `删除默认路由 [...]` 字样，那是兜底生效了。想回滚点一次切换即可，`route add` 会自动补回。
2. **WiFi「显示已连接但实际没有互联网」检测不到。** 例如路由器断了上行：操作系统层面网卡仍在 Up 且有默认网关，工具无法判断，此时需要手动点一下按钮。
3. **自动回切需要工具正在运行**（前台程序，退出后不驻留）。
4. **不要同时开两个实例。** 本版没有加单实例锁，两个实例会同时改跃点/路由，行为可能互相干扰。若发现界面不见了，先从任务栏找一找。
5. **高 DPI（150% 缩放）下界面可能重叠。** 界面是固定像素布局，未在放大缩放下实测。
6. **非中文/英文 Windows**：解析 `netsh` 输出的字段名只覆盖中英文，其它语言下无线配置文件列表可能读不到。
7. **第一次操作可能多等几秒**：`netsh interface show interface` 在本机实测要 4.5 秒（用来发现"已禁用"的网卡），已做缓存 + 指纹判断，只在网卡增删或每 10 分钟才重跑一次。
8. **命令都有超时保护**：所有外部命令（netsh/route/ping）超过 20 秒会被强制终止并在日志里标注 `[命令超时]`，不会让界面无限卡住。

## 界面信息

- **网络适配器表格**：名称、**出口**（● = 当前流量出口）、类型（有线/无线/虚拟）、状态、**跃点数**、速率、IPv4、子网掩码、默认网关、DNS、MAC、管理状态。深绿底 = 当前出口，浅绿底 = 已连接，灰底 = 已禁用。
- **当前连接详情**：流量出口网卡的类型、跃点数、速率、MAC、IP、掩码、网关、DNS、DHCP；下面还列出**所有默认路由的接口跃点/生效跃点**（谁优先一目了然），以及无线部分（SSID、信号强度、无线电类型、信道、收发速率）。
- **已禁用的网卡也会显示在列表里**（状态为"已禁用"），不会被当成"设备不存在"。
- 右上角显示"上次刷新：时间（耗时 x.x s）"，可据此判断采集快慢。
- 按钮：**本地网络切换** / **切换到 WiFi** / 刷新信息 / 设置… / **诊断** / 打开日志。
  「诊断」会生成 `诊断报告.txt` 并打开，里面包含接口跃点数、自动度量、每条默认路由、程序判定的出口等原始数据 —— 排查问题时直接发这个文件。
- 默认每 3 秒自动刷新（可在设置里改成 0 关闭，或改大间隔）；采集变慢时程序会**自动放宽刷新间隔**，保证界面不被采集占满。

## 恢复 / 撤销

- **恢复自动跃点**：设置窗口里点「恢复自动跃点」按钮，会把所有网卡的接口跃点数交回 Windows 自动度量。
- **手动恢复**：网卡属性 → Internet 协议版本 4 (TCP/IPv4) → 高级 → 取消勾选"自动跃点"或改回你想要的数值。
- 工具只做两件系统本身就支持的事：**改接口跃点数**、**启用/禁用网卡**（仅在勾选了 WiFi 禁用选项时会禁用），不写注册表、不改 IP 配置。

## 命令行用法

```powershell
# 只采集并打印当前网络信息（不启动界面，不需要管理员）
powershell -NoProfile -ExecutionPolicy Bypass -File .\NetworkSwitchTool.ps1 -Probe

# 启动界面但不提示提权
powershell -NoProfile -ExecutionPolicy Bypass -File .\NetworkSwitchTool.ps1 -NoElevate

# 直接以管理员身份启动
Start-Process powershell -Verb RunAs -ArgumentList '-NoProfile -STA -ExecutionPolicy Bypass -File ".\NetworkSwitchTool.ps1"'
```

## 实现要点

- 信息采集用 `.NET NetworkInterface` + `netsh` + `route`，**不依赖 WMI**（部分机器/受限环境里 `Get-NetAdapter`、`Get-CimInstance` 会报"拒绝访问"）。
- **网卡清单必须用 `netsh interface show interface` 补充**：网卡被"禁用"后会从 .NET 的 `NetworkInterface` 枚举里彻底消失（表现为"设备不存在"，导致切不回去），而 `netsh` 仍能看到它，并可以重新启用。
- 调用 `netsh` / `route` 时通过 `ProcessStartInfo` 直接传命令行字符串，避开 PowerShell 5.1 对参数内引号的转义（否则 `name="My Adapter"` 这种带空格的网卡名会失败）；输出按控制台代码页解码，中文不乱码。
- "当前流量出口"通过解析 `route print -4` 的 `0.0.0.0/0` 默认路由（取跃点最小者）再按接口 IP 反查网卡，而不是猜。
- 脚本必须以 **UTF-8 带 BOM** 保存，否则 Windows PowerShell 5.1 会按 GBK 解码，中文界面全变乱码。修改脚本时请注意。
- **切换走最短路径**：不再有确认框/成功弹窗，不再做多余的二次快照和固定等待；校验只用一条 `route print`。
  切完把结果写进**状态栏 + 日志**，只有"做不了/失败"才弹窗。典型耗时 1～2 秒。
- **改跃点数必须走 CIM**：`Set-NetIPInterface -AutomaticMetric Disabled` + `-InterfaceMetric N`，写完再回读校验。
  `netsh interface ipv4 set interface metric=` 在这类系统上会**返回退出码 0 但值被"自动度量"覆盖回去**（本机实测），所以只当兜底，且绝不拿退出码当成功依据。
- 判定"当前出口"必须按 **「接口跃点 + 路由跃点」取最小值**：系统会同时返回多条默认路由，而 `route print` / `Find-NetRoute` 的**排列顺序与跃点数无关**（踩过坑：只取第一条 → 出口判错 → 按钮一直往同一块网卡切、切不回来）。来源优先级：`Get-NetRoute` → `Find-NetRoute` → 解析 `route print`（按跃点稳定排序）。
- 按钮用 **"上次切换目标"记忆**（config.json 里的 `lastTarget`）做严格 A↔B 交替，不受出口判定误差影响；没有记忆时才按当前出口推断。
- `netsh interface show interface` 很慢（本机实测 **4.5 秒**，而同机的 `netsh interface ipv4 show interfaces` 只要 60ms），因此：结果缓存 + 用 `.NET` 网卡名单做廉价指纹（名单变了才重跑）+ 用户点按钮时 `-Force` 刷新；刷新间隔再按实际耗时自适应，避免 UI 线程被采集占满而假死。
- **改默认路由自身的跃点才是决定性的一步**：`route change 0.0.0.0 mask 0.0.0.0 <网关> metric <N> if <接口索引>`。
  Windows 里默认路由的"路由跃点"是路由创建时写死的，**改接口跃点不会同步更新它**；如果只对调两块网卡的接口跃点，
  两边总跃点会正好抵消（实测 `1010 = 1010`）→ 路由表打平 → 流量完全不变（这就是"提示成功但没生效"的真正原因）。
  改完必须**按路由表校验**（目标网卡的默认路由生效跃点最小），校验不过就删掉其它默认路由兜底。
- **原生命令输出必须按"原始字节 + 严格 UTF-8 优先"解码**。实测同一台机器：普通实例里 `netsh` 输出 GBK，**管理员（隐藏控制台）实例里 `netsh` 输出 UTF-8**。若按固定编码解码，界面上只是几个字乱码，但"已启用/已禁用"这些状态词会一起烂掉 —— 后果是**明明已启用的无线网卡被判成"已禁用"**，于是白白重置一次网卡、再死等 20 秒超时，最后连接超时失败（这正是"切 WiFi 失败"的真正原因）。现在：读原始字节 → 严格 UTF-8 试解 → 失败才用系统 OEM 代码页（不是控制台代码页，因为后者本身可能就是 UTF-8）。
- **网卡启用状态优先用 CIM（`Get-NetAdapter`）**（名称是 UTF-16，不受控制台编码影响），再用解码后的 `netsh` 结果合并（只要有一边说"已禁用"就按已禁用），双保险。
- `Wait-AdapterAdminState` 增加了"读不到状态就别干等"的保护：状态无法解析时最多等 4 秒就返回，不再空转 20 秒。
- 兼容中英文 Windows：解析 `netsh` 输出时同时匹配中英文关键字。
- 网卡名可以包含空格和中文，全部按名称精确匹配。

## 常见问题

**点了"本地网络切换"，提示目标网卡没有默认网关？**
说明那块网卡虽然启用了但没接入可用网络（网线没插、WiFi 没连、或该网络需要认证）。工具会保持现状不动，避免把流量切到一个死路上。

**WiFi 断开后没有自动切回有线？（或两块以太网之间没自动切？）**
1. 确认设置里「网卡断开后自动把流量切到另一块可用网卡」是勾选的（默认勾选）。
2. 看状态栏/日志有没有 `[自动回切]` / `[自动切换]` 开头的行：
   - 没有 → 说明不满足触发条件（无线其实还在线并有网关、或没有可用的有线网卡、或工具不是管理员权限、或本地网卡全是"自动度量"）。
   - 有但写着"未生效" → 日志里会带每条命令的结果，发我即可。
3. 只有在**工具正在运行**时才会自动切换（它是前台程序，退出后不驻留）。

**WiFi 连不上 / 切到 WiFi 一直失败？**
按这几条依次排查（日志里都会写明原因）：
1. **目标网络不在范围内**：日志会写 `[WiFi] 当前扫描不到「xxx」；可见且已保存的网络：…`，失败弹窗里也会列出**当前可见网络和信号**。照着改选一个即可（开着"自动尝试其它网络"时会自动试）。
2. **无线开关**：飞行模式或机身无线开关关掉时，程序会直接提示"无线电被关闭"，不会干等。
3. **无线服务**：`WlanSvc`（WLAN AutoConfig）没运行的话连接会一直失败 —— 程序会自动尝试启动它。
4. **网卡卡死**：无线网卡经常卡在"正在连接 / 正在断开连接"，程序会自动**重置网卡**（禁用再启用）后重试一次。
5. **密码改过了**：系统里保存的配置文件会连不上，需要先用任务栏 WiFi 列表手动重连一次。
6. **看不到网络列表**：Win11 需要「设置 → 隐私和安全性 → 位置」打开位置服务，`netsh wlan show networks` 才允许列出网络。没有列表时程序会在「设置」里提示你。
7. **没有选 WiFi 名称**：设置里「WiFi 名称」留空时会自动挑"可见且已保存"里信号最强的那个。
8. **等待时间**：单个网络默认最多 15 秒（设置里可调，最快 8 秒）；扫不到的网络只快速试 6 秒。想更激进就把「WiFi 等待(秒)」调到 8。
9. 还是不行就点「诊断」——诊断报告里包含 **`netsh wlan show interfaces` 原始输出、可见网络列表、无线服务状态**，直接发我即可。

**怎么在有线和 WiFi 之间来回切？**
点「有线 ⇄ WiFi」按钮即可，它会自动判断方向：现在走有线就切到 WiFi，现在走 WiFi 就切回有线（切回时优先用上次那块有线网卡）。

**切了之后网络没变化？（重点看这条）**

默认路由的"生效跃点" = **接口跃点 + 路由跃点**，而**路由跃点只在路由被创建时写死，改接口跃点不会同步更新它**。
所以"把两块网卡的接口跃点对调"会出现这种要命的情况：

```
以太网    接口跃点 10   + 路由跃点 1000（旧值） = 1010
以太网 3  接口跃点 1000 + 路由跃点 10（旧值）   = 1010      ← 两边正好抵消，打平！
```

这就是"工具提示切换成功（接口跃点确实写进去了），但实际流量没变"的原因。
现在程序会额外用 `route change` **直接改写默认路由自身的跃点**，并**按路由表校验**；校验不过就删掉其它默认路由，只留目标那条。

排查步骤：
1. 看详情面板的"默认路由"区块 —— 目标网卡那条的**生效跃点必须是最小的**（且不相等）。
2. `switch-log.txt` 里会有每条命令的结果，形如 `路由跃点 [以太网 3] 网关 192.168.137.106 -> 10 : OK`。
3. **已经建立的连接不会迁移** —— 已打开的网页 / 正在跑的下载会继续走旧出口，请**新开页面**验证。
4. 表格"跃点数"列显示 `25 (自动)` 说明"自动度量"还开着，手动值会被覆盖（正常应为 `10`）。
5. 点过「恢复自动跃点」后手动跃点会失效（Windows 重新接管），重新切换一次即可。

**切了之后网络没变化？**
1. 先看表格"跃点数"列：如果显示成 `25 (自动)`，说明这块网卡的"自动度量"还开着，手动值会被覆盖——正常切换后应该显示成 `10`（没有"自动"字样）。
2. 打开 `switch-log.txt`，看每一步的结果（`接口跃点 [x] = 10`、`路由跃点 [x] 网关 ... -> 10 : OK`）；出现"失败"时日志里会带上 `Set-NetIPInterface` 的报错和 netsh/route 的原始输出，把它发我即可。
3. 若默认路由已切换但你想让差别更明显，把设置里的跃点数值差调大（例如 `5 / 5000`）再试。

**想把之前被禁用的网卡启用回来？**
在「设置」里把它选成"本地网络 A"或"本地网络 B"，点保存后按一次「本地网络切换」——它会自动被启用。或者在管理员 PowerShell 里执行：
`netsh interface set interface name="以太网" admin=enabled`

**界面卡顿 / 点了按钮像没反应？**
本机实测 `netsh interface show interface`（用来列出"已禁用"的网卡）单次要 **4.5 秒**，如果每次刷新都跑它，界面就会被占满而假死。现在：这条命令的结果会**缓存**（网卡名单没变就不重跑），并且刷新间隔会根据实际耗时自适应。若你仍感觉卡，把设置里的"自动刷新(秒)"调到 10 或 0。

**想让我确认到底哪里不对？**
点主界面的「诊断」按钮，会生成 `诊断报告.txt`，把它发我即可（里面是接口跃点数、自动度量、默认路由、程序判定的出口等原始数据）。

**点按钮没反应 / 提示需要管理员权限？**
重新通过 `启动网络切换工具.bat` 打开，并在 UAC 弹窗选「是」。
